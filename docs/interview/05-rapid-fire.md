# Быстрое повторение: 80 вопросов-ответов

> Формат: прочитать вопрос → ответить вслух → сверить. Помеченные **[ядро]** —
> спрашивают почти всегда.

## Java (30)

**[ядро] 1. Чем JDK отличается от JRE и JVM?**
JDK = JRE + компилятор и инструменты; JRE = JVM + стандартная библиотека; JVM исполняет
байткод.

**2. Что такое LTS?**
Версия с долгой поддержкой. Java 25 — LTS (до ~2030), 26/27 — non-LTS (6 месяцев).

**3. `==` и `equals` — в чём разница?**
`==` сравнивает значения примитивов или ссылки; `equals` — логическое равенство,
по умолчанию тоже ссылки, но переопределяется.

**[ядро] 4. Почему `Integer a = 127, b = 127; a == b` → true, а для 128 → false?**
Кэш `Integer` от −128 до 127; значения из кэша — один объект, 128 создаёт новые.

**5. Где хранятся строковые литералы?**
В пуле строк (heap, `StringTable`); одинаковые литералы переиспользуются.

**6. Почему `String` неизменяемый?**
Безопасность, потокобезопасность, кэш `hashCode`, использование как ключа и в пуле.

**7. `StringBuilder` vs `StringBuffer`?**
Builder быстрее, не потокобезопасен; Buffer синхронизирован, медленнее.

**8. `final`, `finally`, `finalize`?**
`final` — нельзя изменить/переопределить/наследовать; `finally` — блок после try;
`finalize` — устаревший метод перед сборкой мусора.

**9. Интерфейс vs абстрактный класс?**
Интерфейс — контракт (множественная реализация), абстрактный класс — общая реализация
и состояние, один родитель.

**10. Перегрузка vs переопределение?**
Overload — разные параметры, выбор на компиляции; override — та же сигнатура,
выбор в рантайме.

**[ядро] 11. Что такое `record`?**
Неизменяемый класс данных: `private final` поля, геттеры без `get`, `equals/hashCode/
toString`, компактный конструктор. Не наследуется.

**12. Можно ли добавить поле в `record`?**
Только `static`. Остальные компоненты задаются в заголовке.

**13. `ArrayList` vs `LinkedList`?**
Массив с O(1) доступом vs связный список с O(1) вставкой при известном узле; на
практике почти всегда `ArrayList`.

**[ядро] 14. Как устроен `HashMap`?**
Массив бакетов; индекс `(n-1) & hash`; коллизии — список, при 8 и capacity ≥ 64 —
дерево; load factor 0.75; при превышении — удвоение и rehash.

**15. Зачем `equals` и `hashCode` вместе?**
`hashCode` выбирает бакет, `equals` — ключ в бакете. Нарушение контракта ломает поиск.

**16. `HashMap` потокобезопасен?**
Нет. `ConcurrentHashMap` — да (и не разрешает `null`-ключи).

**17. `List.of` vs `new ArrayList<>()`?**
`List.of` — неизменяемый и не принимает `null`; `ArrayList` — изменяемый.

**18. `Collectors.toList()` vs `stream().toList()`?**
Первый обычно изменяемый, второй — неизменяемый (Java 16+).

**19. `map` vs `flatMap`?**
`map` 1→1, `flatMap` 1→N с «разглаживанием» вложенных коллекций.

**20. Ленивые ли операции Stream?**
Промежуточные (`map`, `filter`) — да; терминальные (`collect`, `count`) запускают
вычисления.

**21. `Optional`: `orElse` vs `orElseGet`?**
`orElse` вычисляет аргумент всегда, `orElseGet` — только если пусто.

**22. Что такое стирание типов?**
Generic-информация есть только на компиляции; в рантайме `List<String>` и `List<Integer>`
— один класс.

**23. PECS?**
Producer Extends, Consumer Super: `? extends T` — читать, `? super T` — писать.

**[ядро] 24. Checked vs unchecked исключения?**
Checked обязаны быть объявлены/обработаны (`IOException`); unchecked — `RuntimeException`
(NPE, свои бизнес-ошибки).

**25. Почему `ApiException` — `RuntimeException`?**
Не засоряет сигнатуры, `@Transactional` откатывает по умолчанию, обрабатывается
глобально.

**26. `try-with-resources`?**
Автоматически закрывает `AutoCloseable`-ресурсы, даже при исключении.

**27. Порядок инициализации класса?**
Статические поля/блоки (один раз) → поля экземпляра → блоки → конструктор.

**28. `volatile` vs `synchronized`?**
`volatile` — видимость и запрет переупорядочивания, не атомарность; `synchronized` —
взаимное исключение + видимость.

**29. Что такое virtual threads?**
Дешёвые потоки JVM для I/O (Java 21+); не ускоряют CPU-bound.

**30. Что такое утечка памяти в Java?**
Объект остаётся достижимым (статическая коллекция, `ThreadLocal`, слушатель), поэтому
GC его не удаляет.

## Maven и Spring (8)

**31. Lifecycle Maven?**
`validate → compile → test → package → verify → install → deploy`.

**32. Scopes зависимостей?**
`compile`, `provided`, `runtime`, `test`; `runtime` — JDBC-драйвер, `test` — TestNG.

**33. Зачем Maven Wrapper?**
Фиксирует версию Maven в репозитории; `./mvnw` качает её сам — у всех одинаково.

**34. `-DskipTests` vs `-Dmaven.test.skip=true`?**
Первый компилирует тесты, но не запускает; второй не компилирует вовсе.

**35. Что такое Maven profile?**
Набор настроек под условие: в проекте `e2e` и `all-tests` меняют `testng.groups`.

**36. Как Spring внедряет зависимости?**
Через конструктор (в проекте), сеттер или поле; контейнер создаёт бины при старте.

**37. Почему `@Transactional` не сработает при вызове `this.method()`?**
Прокси оборачивает внешние вызовы; внутренний вызов идёт мимо прокси.

**38. Что делает `@RestControllerAdvice`?**
Глобально перехватывает исключения контроллеров и формирует ответ (в проекте —
`{"detail": "..."}`).

## TestNG (16)

**[ядро] 39. Порядок аннотаций?**
`@BeforeSuite → @BeforeTest → @BeforeClass → @BeforeGroups → @BeforeMethod → @Test →
@AfterMethod → @AfterGroups → @AfterClass → @AfterTest → @AfterSuite`.

**40. `@BeforeTest` vs `@BeforeClass`?**
`@BeforeTest` — перед блоком `<test>` в XML (может охватывать несколько классов);
`@BeforeClass` — перед одним классом.

**41. Сколько экземпляров класса создаёт TestNG?**
Один на класс (JUnit 5 — на метод). Изменяемые поля класса общие.

**42. Как задать группу?**
`@Test(groups = "smoke")` на методе или классе; запуск `-Dgroups=smoke`.

**43. Как запустить только e2e в проекте?**
`mvn test -Pe2e` (профиль подставляет `testng.groups=e2e`).

**44. `dependsOnMethods`?**
Тест запускается после указанного; если тот упал — SKIP. В проекте не используется.

**45. `priority`?**
Порядок внутри класса, меньше — раньше. Не заменяет изоляцию.

**46. `alwaysRun`?**
Конфигурационный метод выполнится даже при фильтре по группам/упавших зависимостях
(важно для `@AfterMethod`, закрывающего браузер).

**47. DataProvider?**
Поставщик данных: `Object[][]`, `@Test(dataProvider="...")`, может быть параллельным.

**48. `@Parameters`?**
Простые значения из suite XML; только строки/примитивы.

**49. `assertThrows` в TestNG?**
Возвращает `void`. Нужен `expectThrows` (возвращает исключение) или свой helper.

**50. SoftAssert?**
Копит ошибки, падает в `assertAll()`. Жёсткий ассерт прерывает тест сразу.

**51. Как повесить listener?**
`@Listeners`, suite XML или `META-INF/services`; интерфейс `ITestListener`.

**52. RetryAnalyzer?**
`IRetryAnalyzer.retry(ITestResult)` → `true` перезапустить. Прячет симптом, не причину.

**53. Как включить параллельность?**
Suite XML `parallel="methods" thread-count="4"` или Surefire `<parallel>/<threadCount>`.

**54. Почему тест SKIP, а не FAIL?**
Упала зависимость или не выполнилось предусловие (`@BeforeMethod`).

**55. TestNG vs JUnit 5?**
Groups vs tags, dependsOn vs `@Order`, DataProvider vs `@ParameterizedTest`,
`SoftAssert` vs `assertAll`, один экземпляр на класс vs на метод.

**56. Где отчёты?**
`target/surefire-reports/` (txt/XML); в CI — артефакт с `if: always()`.

## Playwright (20)

**[ядро] 57. Locator vs ElementHandle?**
Locator ленивый, переискивает элемент при каждом действии; handle может устареть
после ре-рендера.

**[ядро] 58. Как работает автоожидание?**
Проверяет actionability: attached, visible, stable, receives events, enabled/editable.

**59. Таймауты по умолчанию?**
Действия/навигация — 30 с, web-first assertions — 5 с.
`page.setDefaultTimeout(15_000)`, `PlaywrightAssertions.setDefaultAssertionTimeout(...)`.

**60. Почему не `Thread.sleep`?**
Не знает состояния страницы: либо лишняя задержка, либо всё равно мало.

**[ядро] 61. Browser vs BrowserContext vs Page?**
Browser — процесс; Context — изолированная сессия (cookies/storage); Page — вкладка.

**62. Зачем новый контекст на тест?**
Полная изоляция состояния без запуска нового браузера.

**63. Как замокать API?**
`page.route("**/api/**", route -> route.fulfill(...))`; `page.route` — до действия.

**64. Как дождаться ответа?**
`page.waitForResponse(predicate, action)`.

**65. Как сохранить авторизацию?**
`context.storageState(path)` + `setStorageStatePath(...)` в новом контексте.

**66. Как отладить падение в CI?**
Trace (`tracing().start/stop`), screenshot/video, консоль, `onPageError`, headed локально.

**67. Что такое trace viewer?**
Просмотр записи шагов, DOM-снимков, сети и консоли; открывается `show-trace` или
trace.playwright.dev.

**68. Как открыть iframe?**
`page.frameLocator("iframe").locator(...)`.

**69. Как обработать `confirm`?**
`page.onDialog(dialog -> dialog.accept())` до действия.

**70. Как поймать новую вкладку?**
`page.waitForPopup(() -> click)`.

**71. Как скачать файл?**
`page.waitForDownload(() -> click)` → `download.path()`.

**72. Как загрузить файл?**
`locator.setInputFiles(Path.of(...))`.

**73. Потокобезопасен ли Playwright Java?**
Нет: `Playwright` и его объекты — в одном потоке; параллельно — экземпляр на поток.

**74. Как параллелить E2E?**
Отдельный `Playwright`/`Browser` на поток, контекст на тест, TestNG `parallel=methods`.

**75. Playwright vs Selenium?**
Своя архитектура без WebDriver, автоожидания и web-first assertions, дешёвые контексты,
сеть и trace из коробки; Selenium — зрелее, Grid, реальные устройства через Appium.

**76. Ограничения Playwright?**
Нет настоящего Safari и реальных мобильных устройств, Node-driver в Java, нет
встроенного репортинга, не потокобезопасен.

## HTTP, API, SQL, QA (14)

**77. Идемпотентность?**
Повторный запрос даёт тот же результат: GET/PUT/DELETE — идемпотентны, POST — нет.

**78. PUT vs PATCH?**
PUT заменяет ресурс целиком (у нас — частично, по контракту), PATCH — частичное
изменение.

**79. 401 vs 403?**
401 — не аутентифицирован (нет/битый токен); 403 — аутентифицирован, но нет прав.

**80. 400 vs 422?**
400 — общий неверный запрос (дубликат email в проекте); 422 — семантическая валидация
(нет обязательного поля).

**81. Структура JWT?**
`header.payload.signature`, Base64URL; payload не шифрован — не хранить секреты.

**82. Почему BCrypt?**
Соль + адаптивная сложность, медленный перебор; `matches` без хранения пароля.

**83. Как предотвратить SQL-инъекцию?**
Параметризованные запросы (`?` + аргументы), не конкатенация.

**84. Зачем индекс?**
Ускоряет поиск/сортировку по колонке; цена — место и замедление вставок.

**85. Что такое каскадное удаление?**
Удаление родителя удаляет связанных детей (`ON DELETE CASCADE`); в проекте ещё и
явное удаление задач в сервисе.

**86. N+1 запросов?**
Один запрос на список + по запросу на каждый элемент. Лечится JOIN + группировкой
(как в `GoalService.list`).

**87. Пирамида тестирования?**
Много unit, меньше API, мало E2E. В проекте 11 / 18 / 6.

**88. Что делать с flaky-тестом?**
Воспроизвести, найти причину (ожидания, данные, окружение), починить; retry — временно.

**89. Структура баг-репорта?**
Заголовок, окружение, шаги, ожидаемо/фактически, логи/скриншот/trace, severity/priority.

**90. Smoke vs regression?**
Smoke — «система жива», быстрый; regression — широкий набор перед релизом.
